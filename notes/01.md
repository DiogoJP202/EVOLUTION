# Comandos

- `dotnet new sln -n TaskManager`
    - Cria uma Solution chamada TaskManager. Uma solution é um agrupador de projetos, seu propósito é de organizar o código. Pode ser algo como: TaskManager.Api, TaskManager.Tests, TaskManager.Domain e TaskManager.Infrastructure;
    - .slnx é o formato de solution usado pelo SDK atual.

- `dotnet new webapi -n TaskManager.Api`
    - Cria um projeto ASP.NET Core Web Api chamado TaskManager.Api que roda uma aplicação Web. 
    - Ele contém um `Project.cs`, configurações, arquivo `.csproj` e o endpoint inicial `/weatherforecast`.

- `dotnet sln add TaskManager.Api/TaskManager.Api.csproj`
    - Adiciona o projeto `TaskManager.Api` dentro da solution `TaskManager`.

## Comandos Utéis:

- `dotnet --version`: Verifica a versão do DotNet atual.
- `dotnet new list`: Lista os tipos de projeto que você pode criar.
- `dotnet build`: Compila o projeto.
- `dotnet run`: Compila e roda a aplicação.
- `dotnet clean`: Limpa os arquivos gerados de build.
- `dotnet test`: Roda testes.
- `dotnet add package NomeDoPacote`: Instala uma biblioteca NuGet no projeto.

# Estrutura criada

- `bin/`: Pasta criada automáticamente ao compilar o projeto. Guarda arquivos compilados, como .dll e executáveis intermediários. Não editar nem subir ao git.
- `obj/`: Pasta criada automáticamente, guarda arquivos temporários usados pelo compilador e pelo NuGet. Não subir ao git nem editar.
- `Properties/launchSettings.json`: Configura como vai rodar o projeto localmente. Define:
    - `"applicationUrl": "http://localhost:xxxx"`
    - `"ASPNETCORE_ENVIRONMENT": "Development"` Isso diz que a aplicação está rodando em modo de desenvolvimento.
- `appsettings.json` - Arquivo de configuração geral da aplicação.
    ```json
    "Logging": {
        "LogLevel": {
            "Default": "Information",
            "Microsoft.AspNetCore": "Warning"
        }
    }
    ```
    - Ele controla configurações como log, strings de conexão, flags, etc.
- `appsettings.Development.json`: Configurações específicas para o ambiente de desenvolvimento. A regra é que quando o ambiente é de `Development` ele acrescentar ou sobrescreve o appsettings.json.

## Program.cs

Esse arquivo é o ponto de entrada da aplicação. Hoje ele faz:
- Criar o builder da aplicação;
- Registra serviços com `builder.Services`; 
> Pode ser qualquer recurso da aplicação: controllers, logging, banco, autenticação, OpenAPI, repositórios, services de negócio etc.
- Constrói a aplicação com `builder.Build()`;
- Configura o pipeline HTTP;
- Inicia a aplicação com `app.Run()`;

O trecho `builder.Services.AddOpenApi();` registra os serviços necessários para gerar a documentação.
O trecho:
```c#
if (app.Environment.IsDevelopment()){
    app.MapOpenApi();
}
```
Criar o endpoint HTTP que expõe essa documentação, como `/openapi/v1.json.`
> O endpoint `/weatherforecast` é só um exemplo do template e não usa Controller. Ele usa Minimal API, que é quando você define uma rota direto no `Program.cs`.

> Mapear um endpoint é dizer: "Quando alguém fizer uma requisição para essa rota, execute isso aqui!".

- `app.Run();`: Essa linha faz a aplicação começar a escutar requisições HTTP. Antes dela, você está configurando a aplicação. Depois dela, a API entra em execução.

### Fluxo mental do Program.cs:
CreateBuilder
-> registra serviços
-> Build
-> configura pipeline/endpoints
-> Run

# Conceito Importante

Existem duas formas de criar Endpoints no ASP.NET Core:
`app.MapGet("/rota", () => "resultado");` -> Isso é Minimal Api.

E existe o modelo com Controllers:
```c#
[ApiController]
[Route("api/task")]
public class TasksController : ControllerBase{

}
```
Isso é Controller-Base Api. 

# Controllers

A Controller é uma classe do Asp.Net Core que pode receber requisições HTTP e retornar respostas HTTP. Ela Herda de `ControllerBase`
```c#
[ApiController]
[Route("api/tasks")]
public class TaskController : ControllerBase
{
    [HttpGet]
    public IActionResult Get()
    {
        return Ok("Olá!");
    }
}
```
Ela faz as seguintes perguntas quando chega uma requisição:

- Existe alguma classe que atende essa rota?
- Existe algum método GET nela?
- Quais parâmetros ela recebe?
- Como executar esse método?

Ele não descobre isso automáticamente, ai que entra o `MapControllers();`'
Ao executar `var builder = WebApplication.CreateBuilder(args);`, aqui ainda está construindo a aplicação. Depois ao executar `builder.Services.AddControllers();` é registrado todos os serviços necessários para trabalhar com Controllers. Isso inclui: Descoberta de Controllers, Model Binding, Validação, Serialização Json, filtros,  IActionResult e Atributos com [ApiController].

> Registrar não significa usar necessáriamente.

## O Build()

Depois disso, vem o `var app = builder.Build();`. Aqui o ASP.NET pega tudo que foi registrado e constroi a aplicação de verdade. Até esse momento, não temos nenhuma rota.

## MapControllers()

O comando `app.MapControllers();` faz com que execute algo como: Percorra todas as classes do projeto > Essa classe possui [ApiController] ? > Ela Possui [Route] ? > Quais métodos possuem ? > Registre todas essas rotas.

Depois do MapControllers(), o ASP.NET meio que monta uma tabela interna parecida com:

| Método | URL | Método C# |
|---------|-----|-----------|
| GET | /api/tasks | TasksController.Get |
| POST | /api/tasks | TasksController.Create |
| GET | /api/users | UsersController.List |

> Essa tabela é chamada de Routing Table (Tabela de rotas).

## Explicando

- `[ApiController]`: maraca a classe como uma Controller de API. Também ativa comportamentos automáticos, como validação de entrada.
- `[Route("api/exemple")]`: Define a rota base do Controller.
- `[HttpGet]`: Diz que esse método responde a requisições GET/
- `IActionResult`: Representa uma resposta HTTP. Pode ser `200 OK`, `404 Not Found`, `400 Bad Request` e por aí vai.
- `Guid`: Globally Unique Identifier. É um identificador enorma, dificilmente sendo valores únicos por sua natureza.

# Tipos de models

## Models

É o mais genérico, podend o significar várias coisa: entidade, DTO, ViewModel, modelo de entrada ou saída e modelo usado pelo banco. Em projetos pequenos, `Model` é comum, mas pode virar um problema quando mistura muitas coisas.

##  Entities

Normalmente são usadas para representar coisas principais do domínio e geralmente viram tabelas no banco. Como por exemplo: `TaskItem`, `User`, `Category` ou `Transaction`.

## Domain

Normalmente representam uma camada/pasta mais conceitual, onde ficam entidades, enums, regras e abstrações centrais do negócio. Exemplo:
```txt
Domain/ 
    Entities/
    Enums/
```

## Explicações

- Quando criamos uma property String não nula, precisamos dar o valor dela como String vazia para evitar erros em runtime ou marcar ela como nullable.
